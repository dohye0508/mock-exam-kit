# HWPX 엔진 배치 노트

현재 템플릿과 Windows 한글 2022에서 얻은 구현 참고다. charPr ID·쪽수·축소 비율·글자 수는 보편 규칙이 아니다. [AGENTS.md](../AGENTS.md)와 프로젝트 지시가 우선한다. 수치를 적용하기 전에 현재 템플릿과 렌더링 결과를 확인한다. 절 번호가 5부터 시작하는 것은 옛 AGENTS.md에서 떼어 왔기 때문이다. 1~4절에 해당하는 출제 스타일·역할 분담·그림 요청은 [출제 노하우](authoring-style.md)와 [삽화 요청서](illustration-request.md)에 있다.

## 5. 받은 그림을 확인하고 배치하기
### 5.1 받은 직후
- **글자가 없는지**, 빈 판이 실제로 비었는지 먼저 본다.
- **좌표는 안내도가 아니라 실제 그림에서 잰다.** 전달 메모의 픽셀 좌표가 있으면 쓰고, 없으면 코드로 픽셀을 재서 판 테두리·머리 위치·빈 공간을 찾는다. 안내도와 실제 위치는 대개 다르다.
- 픽셀 → mm: `mm = px / 원본폭px × 삽입폭mm`. 좌표는 **원본 그림 왼쪽 위 기준**이다.

### 5.2 md 문법 (`::: figure file path=… w=<HWPUNIT> h=<HWPUNIT> [cx=<px>]` 아래 줄 단위, 1mm = 283.46 HWPUNIT)
- 아래 `textN`·`tableN`·`bubbleN`·`labelN`·`board`의 x/y/w/h와 꼬리 좌표는 **삽입 크기 기준 mm**다. DELIVERY의 원본 px를 그대로 넣지 않고 5.1의 식으로 환산한다. `figure`의 w/h는 HWPUNIT, `crop`·`cx`만 원본 px다.
- `textN: x,y,w,h[,left|center|right|item][@100|@170|@200] | 줄1 / 줄2`
  - 테두리 없는 글상자다.
  - 함께 쓰는 줄: `textN_font: <charPr id>`, `textN_valign: TOP|CENTER|BOTTOM`, `textN_wrap: 0`(줄바꿈을 한글에 맡김. 판에 글이 많으면 이쪽이 판 폭을 더 잘 채운다), `textN_box: 1`(흰 바탕·테두리 상자. 그림의 빈 판이 너무 작거나 없을 때 이름표 상자로).
- `tableN: x,y,w,h`
  - 빈 판 위의 표다.
  - 함께 쓰는 줄: `tableN_rows: 칸|칸 ; 칸|칸`, `tableN_widths`, `tableN_font`, `tableN_rowh: 줄 높이 mm`.
- `bubbleN: x,y,w,h,꼬리x,꼬리y | 대사`
  - 둥근 말풍선이다.
  - 함께 쓰는 줄: `font: <charPr>`, `bubble_align: center`.
- `labelN: x,y[,w] | 갑`: 이름표.
- `board: x,y,w,h` + `board_table`: 테두리 있는 판 + 표.
- `cx=<px>`
  - 틀 옆에 펜·소품이 붙어 판이 치우칠 때 쓴다. 원본에서 판 가운데 x를 주면 반대쪽에 흰 여백을 덧대 판이 단 가운데에 온다.
  - 이때 `w`는 덧댄 전체 폭 기준으로 다시 잡는다(1536px, cx=737 → 1600px).
  - 얹는 글 좌표는 그대로 원본 기준이다.
- 자주 쓰는 charPr:
  - 큰 제목·강조 숫자: 95
  - 본문 11.5pt: 14·10
  - 10.5pt: 13
  - 10pt: 39
  - 9.5pt: 44
  - 작은 보조 글(시각·방위·층 이름): 56
  - 좁은 말풍선 안의 긴 글: 48(8.5pt)
  - 고딕(계정 이름): 5
  - 9.5pt보다 작은 글자는 보조 글에만 쓴다.

### 5.3 배치 규칙
- **빈 판을 고르게 채운다.** 판이 크면 글자를 키우거나(제목 95, 본문 10) 줄 간격(@170·@200)과 표 줄 높이(`rowh`)를 늘리고, 세로 가운데 정렬한다. 판 안 위아래·좌우 여백이 한쪽으로 몰리지 않게 한다.
- 제목은 판의 세로 가운데에 둔다. 위로 붙으면 "제목이 너무 위에 있다"는 지적을 받는다.
- 판 안의 표·제목은 판의 가운데에, 판은 단의 가운데에 오게 한다(필요하면 `cx`).
- 그림 위 표는 열 폭 합을 빈 판 폭보다 약 3.6mm 좁게 잡아야 판 밖으로 안 나간다. 머리 칸 글은 띄어쓰기 자리에서 줄이 바뀌게 쓴다.
- **인물 대화 장면:**
  - 화자 한 명당 말풍선 하나만 둔다.
  - 말풍선은 그림 위쪽 빈 곳에 둔다. 화자가 많으면 두 줄로 엇갈리게(위 줄·아래 줄) 놓는다.
  - 말풍선 폭은 대사 길이에 맞춘다. 한 줄로 들어가면 폭을 넓혀 한 줄로 만들어, 말풍선 안에 빈 공간이 남지 않게 한다. 대사는 가운데 정렬한다(`bubble_align: center`).
  - 꼬리는 다른 말풍선·꼬리와 겹치지 않게, 말풍선 사이 빈틈으로 지나가게 한다.
  - **이름표는 모두 같은 규칙으로 놓는다.** 각 인물 머리 바로 위에 두고 꼬리 끝이 이름표를 가리키게 하면 누가 말했는지 헷갈리지 않는다. 두 사람 사이에 걸치거나 다른 사람의 손·머리카락 옆에 붙은 이름표는 어색하다. 발밑·화면 끝처럼 먼 곳에도 두지 않는다.
  - 말풍선 줄이 의미 단위에서 끊기게 한다("을과 병 중 한 / 명이"는 나쁘고, "을과 병 중 한 명이 / 방에 없었어."가 좋다).
- 자료 상자 옆에 작은 그림을 나란히 놓는 배치는 쓰지 않는다. 상자가 좁아지고 그림이 작아져 지저분해진다.
- 문항 md에 `@inline`을 쓰면 선택지를 한 줄에 늘어놓는다(글자 수 자동 판정이 세로로 돌릴 때).
- 그림 두 장을 한 문항에 이어 넣을 때 `caption=`은 위아래 여백을 크게 차지하므로 쓰지 말고 발문으로 설명한다.
- 그림 폭은 보통 72~100mm다. 너무 작으면 "사진이 작다"는 지적을 받고, 너무 크면 한 문항이 단을 차지해 4쪽 맞추기가 어려워진다.

## 6. 가독성 (본문)
- **낱말이 줄 끝에서 쪼개지면 안 된다**('처음으/로', '2/학년'). 한글(2022) 실측 결과, 문단 모양 `breakNonLatinWord="BREAK_WORD"`가 어절 단위이고 `"KEEP_WORD"`가 글자 단위다(이름과 반대). build가 모든 문단을 BREAK_WORD로 바꾼다.
- **외톨이 줄**(문단 마지막 줄에 1~3글자)을 남기지 않는다. 빌드 뒤 `python tools/widows.py <pdf>`로 찾고 문장을 줄이거나 나눈다. 발문과 `[3점]`은 줄바꿈 없는 공백(U+00A0)으로 연결해, 배점만 다음 줄에 남지 않게 한다. 단 폭이 부족하면 발문의 마지막 어절과 배점이 함께 넘어간다.
- **늘어진 줄**(양쪽 정렬 때문에 띄어쓰기가 크게 벌어진 줄)을 고친다. 고치는 방법은 셋이다.
  - 문장을 줄여 한 줄에 넣는다.
  - 의미 경계에서 `<br>`로 끊는다. `<br>`로 끝나는 줄은 늘어지지 않는다.
  - 긴 항목을 한 줄짜리 항목 여러 개로 나눈다.
- `<br>`은 의미 경계(문장 끝, "단," 앞, 쉼표 뒤)에만 쓴다. 아무 데나 넣으면 오른쪽이 들쭉날쭉해져 "가독성이 나쁘다"는 지적을 받는다.
- 자료 상자 항목은 한두 줄 안으로 쓴다.
- 줄 길이 감: 자료 상자 한 줄 ≈ 한글 27글자(띄어쓰기는 반 글자). 10pt 한글 한 글자 ≈ 3.2mm, 띄어쓰기 ≈ 1.6mm. 말풍선 안쪽 폭은 폭 − 3.2mm다.
- **수식은 LaTeX**로 쓴다.
  - 예: `$\frac{2}{5}$`, `$\sum_{k=1}^{m} a_k = -10$`, `$a_n = -n$`.
  - `hwpx.latex_to_hwp`가 한글 수식으로 바꾼다. 변환되는 명령: \frac, \sqrt, \sum, \left|…\right|, ^, _, \le, \ge, \times, \cdot 등.
- `~`는 빌드 때 가운데 높이의 `∼`(U+223C)로 바뀐다(한글 글꼴의 `~`는 위로 떠 보인다).
- 표·「<보 기>」·자료 상자의 오른쪽이 잘리지 않는지 본다. 들여쓴 문단 안에서는 폭이 그만큼 줄어든다.

## 7. 지면 (현재 탐구형 템플릿의 배치 예)
- 기존 4쪽 탐구형 템플릿을 기준으로 한 예다. 실제 목표는 프로젝트 설정을 따른다. 마지막 쪽 오른쪽 단은 '확인 사항' 상자와 겹치지 않게 한다.
- 문항은 쪼개지지 않고 통째로 한 단에 들어간다. 넘치는 원인은 대개 총 분량보다 단 끝의 빈 공간(조각화)이다.
  - `python tools/qpos.py <pdf>`로 문항 시작 위치를 본다.
  - `python tools/colfill.py <pdf>`로 단별 남은 여백(mm)을 본다.
- 줄일 때:
  - 실제로 줄 수가 줄어야 효과가 있다.
  - 방법은 표 눕히기, 그림 폭 줄이기, 반복되는 상자 줄 지우기 등이다.
  - 정답에 필요한 단서는 지우지 않는다.
- **여백은 고르게 나눈다.** 평가원 시험지처럼 문항마다 아래에 풀이 공간이 비슷하게 남아야 한다.
  1. 문항을 고친 뒤에는 헤더의 `{gap=}`을 기본값으로 되돌린다.
  2. 빌드한다.
  3. `python tools/balance.py <pdf> content/N교시.md --apply`를 실행한다. 단마다 남는 여백을 그 단의 문항 사이에 `{gap=N}`(빈 줄 1개 ≈ 2.47mm)로 나눠 준다.
  4. 다시 빌드하고 `qpos.py`로 단 배치가 그대로인지 확인한다.
  - 그림을 넣어 140mm가 넘는 문항이 생기면, 한 단에 둘이 못 들어가 뒤 문항이 연쇄로 밀린다(5쪽이 되는 주원인). 이때 `qpos.py`로 단마다 들어간 문항을 보고, 모자라는 높이만큼 줄인다. 줄이는 순서: <보기>·상자 항목을 한 줄로, 늘어선 선택지를 `@inline`으로, 그림 폭을 5~10mm 줄임, 단 끝 문항 뒤 `{gap=0}`.
  - 단 하나가 크게 비면(예: 150mm) 뒤 문항을 몇 mm만 줄여 그 단으로 끌어올리고, 뒤쪽에 생긴 여유에 그림을 더 넣는다.
  - `balance.py`는 기존 `{gap=}`에 더한다. 되돌리지 않고 두 번 적용하면 문항 사이만 벌어지고 마지막 문항 아래가 좁아진다. `colfill.py`로 봤을 때 단 끝 여백이 문항 사이 간격과 비슷해야 맞게 된 것이다.
- 그림이 많아 크게 넘칠 때(예: 6쪽) 쓰는 도구와 요령:
  - `python tools/qheights.py <pdf>`: 문항별 높이(mm)와 합계를 본다. 4쪽 용량은 대략 단 295mm(1쪽)·327mm(2쪽부터) × 8단이고, 단 끝 낭비와 '확인 사항' 상자(약 22mm)를 빼면 문항 합계가 약 2,450mm 이하여야 한다.
  - **그림의 빈 바닥·하늘 잘라 내기**: `::: figure file … crop=x0,y0,x1,y1`(원본 px). h는 잘린 비율로 다시 계산(h = w × (y1−y0)/(x1−x0)). 얹은 글 좌표는 원본 왼쪽 위 기준 그대로 둔다. 글자를 줄이지 않고 높이를 10~20mm 줄일 수 있어 먼저 쓴다.
  - `python tools/figscale.py <md> <문항> <폭mm> [--nth k]`: 그림 폭을 바꾸고 얹은 글·표·말풍선 좌표를 같은 비율로 맞춘다. 글자 크기는 그대로라 렌더해서 넘치는지 본다.
  - 작은 그림 두 장(사진 + 도식)은 PIL로 한 장에 가로로 이어 붙이면 높이가 하나 몫만 든다(예: 4교시 11번 샤워실 사진 + 배관도).
  - 표 행 높이: `::: table widths=… row_h=1250`(이전 HWPX 기본 1600; Typst 기본은 원본 표의 행 높이). 한 줄짜리 행이 많은 표에서 행마다 약 1mm 준다.
  - 발문을 한 줄로: 한 줄은 약 36자. 넘치는 2~3글자 때문에 생긴 줄을 없애면 문항당 5mm씩 준다.
  - `side=right`(상자·표 오른쪽에 그림)는 상자 줄이 아주 짧을 때만 쓴다. 상자가 좁아져 글자 사이가 크게 벌어진다.
  - `python tools/reorder.py <md> <옛 번호 순서>`: 문항 순서를 바꿔 큰 문항과 작은 문항을 한 단에 짝짓는다. 번호가 바뀌므로 사용자에게 바뀐 번호를 알린다.

## 8. 렌더링 확인 (빠뜨리지 말 것)
- 쪽 전체를 작게 본 것으로 확인했다고 하지 않는다. **바뀐 문항은 실제 크기로 잘라서** 본다: `python tools/qcrop.py <pdf> <출력폴더> 130 4 7 9`.
- 확인 항목:
  - 글자 잘림·겹침
  - 낱말 쪼개짐·외톨이 줄·늘어진 줄
  - 말풍선 꼬리와 이름표 위치
  - 빈 판과 얹은 글의 정렬과 여백
  - 판·표의 가운데 맞춤
  - 단 넘침, 확인 사항 상자 겹침
  - 범례·축 글자
- 배치가 이상해 보이면 다 고치기 전에 **일찍 알린다**.
- 확인하지 않은 인쇄 품질은 확인했다고 말하지 않는다.

## 9. 제작·검증 절차
- 먼저 `git status`로 다른 작업자의 미커밋 변경을 확인한다. 일괄 초기화·덮어쓰기·무분별한 `git add .`를 하지 않는다. 커밋·푸시는 사용자가 요청할 때만 한다.
- 여러 문항을 나눠 고칠 때:
  - 에이전트마다 **한 파일, 정해진 문항 구간만** 맡긴다.
  - 같은 파일을 둘이 고치면 편집 도구로 해당 구간만 바꾸고 파일 전체를 덮어쓰지 않는다.
  - 빌드(한글 변환)는 한 번에 하나씩 돌린다(잠금 파일 사용).
- 명령:
  - `python -m examkit check content/N교시.md`: 문항 수·[3점] 수·정답 분포·보기 세트.
  - `python -m examkit build content/N교시.md -o output/<폴더>`: HWPX → HWP·PDF, 쪽수 출력.
  - `python -m examkit review content/1교시.md content/2교시.md -o output/review_<회차>`: 정답 선택지를 `@status` 색(빨강 keep, 초록 mod, 파랑 new)으로 칠한 검토본. 사용자에게는 이 검토본과 정답 표시 없는 풀이용 PDF를 함께 준다.
- 전달 전 확인:
  - PDF 생성 시각을 확인한다.
  - 바뀐 문구가 PDF 텍스트에 실제로 있는지 검색한다.
  - 명령의 종료 코드를 확인한다. 실패한 빌드 뒤에 옛 파일이 복사된 적이 있다.
- 세션을 마칠 때 변경 파일, 검증 결과, 미완료 사항을 남긴다.

## 10. 한글(HWP) 변환 환경
- 변환은 한컴오피스 COM(`HWPFrame.HwpObject`)으로 한다. `examkit/convert.py`는 하위 프로세스에서 실행되며, 240초가 지나면 오류로 끝내고 잠금으로 동시 실행을 막는다.
- **자동화 보안 모듈이 필요하다.** 없으면 파일마다 '접근 허용' 창이 뜨고, 숨은 창에서는 그대로 멈춘다.
  - 한컴 공식 `보안모듈(Automation).zip`의 `FilePathCheckerModuleExample.dll`을 둔다.
  - 실제 레지스트리 `HKCU\Software\HNC\HwpAutomation\Modules`에 `FilePathCheckerModule` = DLL 절대 경로를 넣는다.
  - 확인은 `RegisterModule("FilePathCheckDLL", "FilePathCheckerModule")`의 반환값이 True인지로 한다. 다른 AI의 격리 환경에서 쓴 레지스트리 값은 실제 레지스트리에 없을 수 있다.
  - 이 PC의 한글 2022는 32비트이므로 x86 DLL을 쓴다.
- 변환이 멈추면 해당 자동화가 생성한 프로세스인지 먼저 확인한다. 사용자가 열어 둔 한글 문서를 일괄 종료하지 않는다.
- 열려 있는 출력 파일은 덮어쓸 수 없으니 회차마다 새 출력 폴더를 쓴다.
- 한글 PDF는 8절 쪽을 A4로 약 **0.754배** 줄여 내보낸다. PDF에서 잰 크기는 이 비율로 환산한다(`qcrop.py`가 실제 크기로 보정한다).
