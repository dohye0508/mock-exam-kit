## 사람 삽화 외의 자료도 활용하기
자료의 역할을 먼저 정한다. 대화에는 인물·말풍선, 규칙에는 공지·기록표, 순서에는 일정·재생 목록, 위치에는 지도·안내판, 사건에는 기사, 시대의 단서에는 사료·유물·건축물 등 다양한 형식이 있다.
원본 기출의 내용을 그대로 학교 문제에 옮기는 것이 아니라 자료를 제시하는 형식과 정보 배치를 참고한다.

## 다운로드 원칙
- 기존 사탐·한국사·통합사회 JPG는 약 2.90GB, 추가 과탐·직탐 PDF는 약 4.256GB이며 Git LFS로 관리한다. 목록·문서를 읽기 위해 원본 전체를 받을 필요는 없다.
- 먼저 위 예시 중 필요한 것만 열어 본다. 추가 후보가 필요하면 과목·학년도·문항 경로를 좁힌다.
- 다운로드한 파일과 AI에게 입력하는 이미지는 별개다. 모든 이미지를 한 번에 모델에 입력하지 않는다.
- 이미지 원본 존재 여부는 파일 내용으로 확인한다. LFS 포인터는 작은 텍스트 파일이며 첫 줄이 `version https://git-lfs.github.com/spec/v1`이다.
- GitHub 비공개 저장소 접근 권한과 Git LFS 설치가 필요하다. 다운로드 실패와 후보 부재를 구분한다.

### 이미 복제한 저장소
저장소 루트에서 실행한다. 아래 설정은 해당 저장소에만 적용하며 기존 다운로드 파일을 삭제하지 않는다.

```powershell
git lfs install --local --skip-smudge
git lfs pull --include="assets/reference/tongsarang/한국사/2027/2027_09_korhis_01.jpg" --exclude=""
```

여러 경로는 --include에 쉼표로 나열할 수 있다. 특정 과목·연도 전체가 실제로 필요할 때만 와일드카드를 사용한다. 범위 없는 `git lfs pull`은 기본 절차가 아니다.

### 새로 복제할 때 (PowerShell)
이미 저장소가 있는 환경에서는 다시 복제하지 않는다. 원본 자동 다운로드를 생략하려면 clone 전에 환경 변수를 설정한다.

```powershell
$previousLfsSkip = $env:GIT_LFS_SKIP_SMUDGE
try {
    $env:GIT_LFS_SKIP_SMUDGE = "1"
    git clone https://github.com/dohye0508/mock-exam-kit.git
    if ($LASTEXITCODE -ne 0) { throw "git clone 실패: 원인을 확인한 후 다시 시도하세요." }
} finally {
    if ($null -eq $previousLfsSkip) {
        Remove-Item Env:GIT_LFS_SKIP_SMUDGE -ErrorAction SilentlyContinue
    } else {
        $env:GIT_LFS_SKIP_SMUDGE = $previousLfsSkip
    }
}
Set-Location mock-exam-kit
git lfs install --local --skip-smudge
```

clone 실패 시 다음 단계로 진행하지 말고 원인을 확인한다. 이후 위의 파일 단위 pull 명령으로 원본을 가져온다.

## 검색 목록의 현재 상태와 확장 방향
- 수집 당시의 과목별 OCR 목록과 검색 HTML은 별도 로컬 수집 폴더에 있으며 현재 이 저장소에는 포함되어 있지 않다. 다른 세션에서 자동으로 접근 가능하다고 가정하지 않는다.
- 위 11개 예시는 저장소 안의 경로만으로 다시 찾을 수 있다.
- `assets/reference/catalog/archive.jsonl`은 과탐·직탐 전체 PDF 목록이다. `additional-sources.json`은 최초 대표 미리보기 14개 목록이다. 전체 13,985문항의 발문·OCR 목록은 아직 구현되지 않았다. 향후 같은 디렉터리에 과목별 경로·학년도·시험 구분·문항 번호·발문·OCR·자료 유형을 추가할 수 있다.
- 자료 유형 태그에는 자동 추정인지 육안 확인인지 표시한다. 모든 항목을 검수한 것으로 오인하게 만들지 않는다.
- 소수의 미리보기와 일반 텍스트 목록은 일반 Git, 대량 원본은 기존 Git LFS에 두는 구성을 권장한다. 원본 저장소 분리는 별도 작업이며 지금 수행하지 않는다.

## 결과를 기록할 때
각 새 자료의 요청서나 작업 기록에 다음을 남긴다.
- 대상 문항과 필요한 판단 단서
- 자료 유형과 선택 이유
- 실제 확인한 참고 원본 경로
- AI 그림 / 문서·코드 요소의 구분
- 최종 삽입 크기와 비워 둘 공간
- 생성 파일 경로, 검증한 내용, 남은 문제

기존 삽화 10장은 사용 가능한 후보이며 모두 넣어야 하는 할당량이 아니다. 문항과 시험지 전체의 가독성을 기준으로 선택한다.
