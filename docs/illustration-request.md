# 삽화 요청서: 작업 AI가 이미지를 못 만들 때 외부 생성기에 맡기는 방법

> 범용 규칙이 아니라 **현재 작업 환경의 우회 절차**다. 작업 AI(이 프로젝트에서는 Claude)가 이미지를 생성하지 못해, 사용자가 요청서 묶음(zip)을 ChatGPT에 올려 그림을 받아 왔다. 이미지를 직접 만들 수 있는 환경이면 1~3절은 건너뛰고, 4·5절(받은 그림 확인·글 얹기)과 [출제 노하우 5절](authoring-style.md)의 '글자는 문서에서' 원칙만 지키면 된다.

문서 작업 AI는 **요청서를 쓰고, 받은 그림을 확인하고, 글을 얹는** 일을 맡는다. 글자·숫자는 그림에 절대 넣지 않는다([출제 노하우 5절](authoring-style.md)).

## 1. 요청 묶음의 구조

```
assets/illust/handoffN/            N은 회차. 묶음째로 zip해 사용자에게 넘긴다
  PROMPT.md                        ChatGPT에 붙여 넣을 요청서 전문(아래 템플릿)
  <id>/layout.png                  빈 판·인물 위치 안내도(코드로 그린 사각형+빨간 글)
  <id>/style_1.png, style_2.png    그림체 기준: 지난 회차에 받은 그림 중 2장
  DELIVERY.md                      ← 생성 쪽이 돌려주는 납품 기록(빈 판 좌표·머리 위치)
```

- 완성 PNG는 `assets/illust/<id>.png`에 저장하게 한다. 파일명은 `교시접두_내용_NN.png`(예: `culture_promo_poster_02.png`, `hist_rne_final_01.png`). 접두는 geo/life/culture/hist.
- 요청 묶음은 작업 흔적이라 저장소에 올리지 않는다. 인곽 프로젝트의 과거 묶음(handoff5~7)은 `ISHS_Wiki/인곽생활_모의고사/handoffN_그림요청.zip`에 보관되어 있다. 승인된 최종 PNG와 코드 그림 소스만 저장소에 둔다.
- `layout.png`는 PIL로 1536×1024 흰 바탕에 빈 판(검은 사각형+빨간 라벨), 인물 자리(파란 타원), 메모 한 줄을 그린다. 안내용 윤곽은 "그리지 말 것"이라고 적는다.

## 2. PROMPT.md 템플릿 (실제로 쓴 형식 그대로)

```
시험지(수능 양식, 흑백 인쇄)에 넣을 **글자 없는 그림 N장**을 만들어 줘. 함께 올린 `handoffN` 폴더에는 그림마다 폴더가 있고,
각 폴더에 `layout.png`(빈 판·인물 위치 안내)와 `style_1.png`, `style_2.png`(지난번에 네가 만든 그림 중 그림체 기준)가 들어 있다.
글자·숫자는 내가 문서에서 직접 얹으니, **그림에는 글자·숫자·기호를 하나도 넣지 말고**, 글이 들어갈 자리는 **순백의 빈 판**으로 남겨 줘.

[공통 규칙]
- 크기: 1536×1024 PNG. (정사각 화면은 1254×1254)
- 그림체: 지난번 그림들과 같게. 흑백(회색조), 흰 배경, 선명한 윤곽선, 회색 1~2단계, 질감 최소. 작게 인쇄해도 알아볼 수 있게 선을 굵게.
- 빈 판: 순백, 선·격자·글자 없음, 정면(원근 없음). 위치는 layout.png와 최대한 같게. **판은 넉넉하게 크게**(글이 여러 줄 들어간다).
- 인물: 실존 인물을 닮게 그리지 않는다. 표정은 단순하게. 학생은 교복이나 체육복 차림.
- 금지: 글자, 숫자, 로고, 컬러.
- 저장: `C:\...\mock-exam-kit\assets\illust\<id>.png`. 다 만든 뒤 빈 판 좌표(x, y, 폭, 높이 px)와 인물 머리 위치를 `assets/illust/handoffN/DELIVERY.md`에 적는다.

[교시 이름]
1. `<id>`: 장면 한 줄 설명.
   - 그릴 것(인물·사물 수, 방향, 구도)을 항목으로.
   - 빈 판의 위치와 용도(제목 띠, 본문 판, 이름표, 말풍선 자리 등).
2. `<id>`: …
```

- 그림마다 **인물/사물 수와 방향, 빈 판의 개수·용도·대략 위치**를 꼭 적는다. 빠뜨리면 자리 수나 구도가 요청과 달라져 문항을 고쳐야 한다.
- 글이 많이 들어갈 판(포스터 본문, 안내문)은 "판을 넓게"라고 명시한다. 좁게 오면 글자를 줄이지 말고 다시 요청한다.
- 그래프·도식은 요청하지 않는다. 값이 정답을 좌우하는 그림은 코드로 그린다(`assets/illust/sources/` 참고, 600dpi, 글자 8.5pt 이상).

## 3. DELIVERY.md에 받을 것

```
## <id> — 한 줄 설명
크기: 1536×1024px. 파일: assets/illust/<id>.png
| 빈 영역 | x | y | 폭 | 높이 |
| 제목 띠 | 130 | 135 | 260 | 55 |
머리 중심: [365, 225], [785, 230]
```

좌표는 PNG 왼쪽 위 기준 px이며 테두리를 피한 안전 영역이다.

## 4. 받은 직후 확인
- 원본을 직접 열어 본다. 글자가 없는지, 빈 판이 실제로 비었는지, **인물·자리·상자 수와 방향이 요청과 같은지** 본다. 생성 AI는 요청과 다르게 그리기도 한다(예: 8칸 요청에 6칸, 무대 스크린 요청에 벽 포스터). 달라졌으면 틀린 그림에 맞춰 문항 조건을 바꾸지 말고, 다시 요청하거나 그 구도에 맞춰 문항을 고칠지 사용자와 정한다. 문항을 쓰는 중인 작업자에게도 바로 알린다.
- 비율이 다르게 오면 자르지 말고 흰 여백을 덧댄다(`figure file`의 `h=`가 자동 처리).
- 좌표는 안내도가 아니라 **최종 그림에서** 잰다. DELIVERY 값이 있으면 쓰고 없으면 코드로 픽셀을 재서 판 테두리·머리 위치를 찾는다.

## 5. 글 얹기 (요약 — 문법 전체는 [HWPX 배치 노트](hwpx-layout-notes.md) 5절)
- 환산: `mm = px / 원본폭px × 삽입폭mm`. 좌표는 원본 왼쪽 위 기준. `figure`의 `w/h`는 HWPUNIT(1mm=283.46), `crop`·`cx`만 px.
- `textN`(글상자), `tableN`(판 위 표), `bubbleN`(말풍선), `labelN`(이름표), `textN_box: 1`(흰 테두리 상자: 그림에 이름판이 없을 때).
- 빈 바닥·하늘은 `crop=x0,y0,x1,y1`로 잘라 높이를 줄인다. 그림과 표의 좌우 끝을 맞추려면 그림 폭을 표 폭과 같게 하고 `cx`로 여백을 덧댄다.
- 원근이 있는 판(기울어진 포스터·화면)은 글상자 대신 PIL로 평면에 글을 그린 뒤 `Image.transform(..., PERSPECTIVE)`로 네 꼭짓점에 맞춰 합성하고 새 파일(`*_02.png`)로 저장한다.
- 코드 화면은 줄마다 글상자를 따로 두고(들여쓴 줄은 x를 4~5mm 옮김) 작은따옴표를 쓴다(큰따옴표는 둥근 따옴표로 바뀜). 글꼴은 고딕(charPr 63 등).
- 그림 폭을 바꾸면 `tools/figscale.py`로 얹은 글 좌표를 함께 바꾸고 `tools/qcrop.py`로 잘라 넘침을 확인한다.
- 말풍선·글상자가 인물 얼굴을 가리지 않게 하고, 판 안 글은 꽉 차지도 여백이 지나치게 남지도 않게 한다.
