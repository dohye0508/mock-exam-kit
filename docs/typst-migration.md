# Typst 출력 연결

**원본 동일성은 완료되지 않았다.** 원본에서 읽는 서식과 자체 추가 배치값의 구분은 [서식 점검 기록](source-fidelity-audit.md)을 따른다. 아래 실행 성공과 지원 기능 목록은 원본 렌더링 동일성을 뜻하지 않는다.

`codex/typst-backend`의 기본 `build`, `review`, 표지와 최종 합본을 Typst 경로에 연결했다. 본문·표지는 편집 가능한 텍스트/도형 명령으로 생성하며 완성 문제지 이미지를 배경으로 쓰지 않는다. 정답표·해설·PDF 병합은 기존 PyMuPDF 빌더를 사용한다. 한글 실행·COM은 필요하지 않다.

## 준비와 실행

엔진 Python 코드, Typst 틀, 다섯 과목과 두 표지의 양식 데이터는 저장소의 `runtime/`에 포함한다. 외부 작업 폴더나 원본 HWP는 빌드에 필요하지 않다. 글꼴 바이너리는 공개 재배포 허가가 확인되지 않아 제외하며, 보유한 정확한 글꼴 묶음을 로컬에서 가져와야 한다. 같은 이름의 다른 글꼴이나 원본 HFT 파일만으로 대체할 수 없다.

```powershell
python -m pip install -r requirements.txt
python tools/import_typst_fonts.py 'C:/path/to/보유한/fonts'
# Typst가 PATH에 있으면 다음 환경변수도 생략한다.
$env:TYPST_EXE='C:/path/to/typst.exe'
python -m examkit build content/example.md -o output/example
python tools/build_final.py output/demo docs/examples/format-demo.md
```

가져오기에는 전달용 묶음의 루트 폴더도 지정할 수 있다. `python tools/import_typst_fonts.py`는 설치된 144개 원본 글꼴의 SHA-256을 검사한다. 파일 목록은 `runtime/fonts-manifest.json`에 있다. 글꼴을 내려받거나 시스템 글꼴로 대체하지 않는다. 필요한 글꼴 묶음이 없는 사람은 코드만 복제해서 PDF를 만들 수 없다.

`EXAMKIT_TYPST_ROOT`는 다른 엔진을 명시적으로 쓸 때만 지정한다. 기본값은 저장소의 `runtime/`이다. HTML 자료 그림에는 Chrome/Edge가 추가로 필요하다. 로컬 검증에는 Windows와 Typst 0.15.1을 사용했다.

`python tools/bundle_typst.py output/portable-typst`는 커밋된 소스·양식과 설치된 글꼴·Typst 실행 파일을 로컬 폴더로 묶는다. 임시 테스트 폴더나 미추적 개인 파일은 수집하지 않는다. 이 글꼴 포함 묶음은 공개 커밋 대상이 아니다. [엔진 구성과 양식 추출](../runtime/README.md)을 참고한다.

## 편집 범위

- 본문은 `body_template: science`(기본)·`social`·`korean`·`english`·`math`; 표지는 `cover_template: korean`·`math`다. `elective: 화법과 작문|언어와 매체|확률과 통계|미적분|기하` 중 해당 과목의 이름 하나를 지정하면 원본 선택과목의 머리글·단 크기·마지막 안내를 사용한다. 문항 입력은 여전히 5지선다·2/3점 스키마다. 수학 주관식·4점 입력까지 연결한 것은 아니다.
- `body_title`, `year`, `exam`, `period`와 표지 문구를 바꿀 수 있다. `area`는 과탐·사탐·수학, `subject`는 과탐·사탐에 적용한다. 국어·영어 원본의 영역명은 이미지여서 유지하며, 다른 영역명을 입력하면 무시하지 않고 오류를 낸다. 선택과목은 원본의 영역명·교시를 유지한다. `pages: auto`는 실제 쪽수로 표지/합본을 만든다. 숫자는 최소 쪽수를 확보하되 내용이 초과하면 오류로 처리한다.
- 상자·표·그림·대화·보기·짝짓기·선택지, 그림 위 글상자/말풍선/표, 나란히 배치, `{page}`, `{col}`, `{gap}`, `@status`를 연결했다. `@center`는 제목 서체, `@c`는 본문 서체로 가운데 정렬한다.
- 선택지는 실제 글폭·수식 폭과 한 글자 크기의 여유를 검사해 5개 한 줄 → 3+2 → 2+2+1 → 1개씩 순서로 고른다. 한 줄은 원본 번호/내용 10칸 표(과탐 13번, 사탐 12번), 3+2와 2+2+1은 원본 문단의 탭 위치와 행간을 재사용한다. `@choices auto|5|3|2|1`로 문항별 지정할 수 있다. `@inline`은 기존 한 줄 지정과 호환되며, 원본 칸을 넘는 강제 한 줄 배치는 오류로 알린다. 짝짓기 `grid`의 열은 그대로 유지한다.
- 자료 뒤 `?` 질문문은 과탐 `02-문제(2행)`·사탐 `문제 아래 - 일반` 스타일을 사용한다. 보기는 대응 원본 항목의 표지 문자와 본문 글자 모양을 각각 유지하며, 긴 항목의 줄바꿈·들여쓰기는 해당 원본 문단 서식을 따른다.
- `question_spacing: auto`(기본)는 단 아래에 남은 공간을 문항 사이와 마지막 문항 아래에 나누되, 문항 사이에 추가하는 간격을 원본 발문 두 줄 높이 이하로 제한한다. 큰 빈 공간을 전부 문항 사이에 밀어 넣지 않는다. 문항 내부의 상자·보기·선택지는 함께 이동하며, 쪽수와 단 배치는 유지한다. `compact`는 이 분배를 끄고 원본 문단 간격만 사용한다. `{gap=N}`은 여기에 빈 문단 N개를 더한다. 단을 넘겨 이어지는 문항이 있는 단은 재분배하지 않는다. 한 단에 들어가는 문항은 통째로 유지하므로 긴 문항 앞에는 남는 공간이 생길 수 있다.
- 수식은 매번 입력에서 생성한다. MathText에 `matrix`·`pmatrix`·`bmatrix`·`Bmatrix`·`vmatrix`·`Vmatrix`·`cases` 환경의 행/열 배치를 추가했다. 분수·첨자·중첩 행렬에도 적용하며, 본문·보기·선택지·해설에서 같은 처리기를 사용한다. 한글식 `matrix {a&b#c&d}`, `cases {x&x>0#-x&x<0}`와 기존 `over`도 지원한다. 원본 HancomEQN만 사용하고, 없는 이중 세로선 글리프는 같은 글꼴의 세로선 두 개로 구성한다. `array`의 `{lcr}` 열 정렬과 `aligned`·`align`·`align*`의 좌우변 정렬도 지원한다. array의 수직선·폭 지정과 전체 한글 수식 문법은 지원하지 않으며 오류를 낸다. [행렬·경우 나눔 예제](examples/math-grids.md)를 참고한다.
- `::: passage range=1-3` 블록은 첫 문항에 공통 지문을 붙이고 `[1∼3]` 안내를 자동 생성한다. 국어는 원본의 연결 테두리 문단을 사용한다. `prompt=다음_자료를_읽으시오.`로 안내를 바꿀 수 있다. `--only`로 중간 문항만 뽑아도 공통 지문을 포함한다.
- `::: figure file ... wrap=left|right`는 바로 앞 일반 문단 옆에 그림을 놓고 글을 흐르게 한다. 상자/표 옆 배치는 기존 `side`를 사용한다. 그림이 단 폭 이상이면 오류를 낸다.
- 본문·보기·선택지·그림 글자에서 `<br>`은 강제 줄바꿈이다. `textN_wrap: 1`은 기존 어절 사전 줄바꿈을, `0`은 엔진의 자연 줄바꿈을 사용한다. `0`도 글상자 경계를 넘어 출력하는 설정은 아니다.
- `--no-compile`(`--no-convert` 별칭)은 `.typ`와 `.assets`까지만 만든다. PDF 컴파일·쪽수·머리글·문항 번호 검사가 끝나야 기존 PDF를 교체한다.

## 검증과 한계

`python tools/check_typst_migration.py`는 중립적인 새 문항으로 다섯 과목과 선택과목 다섯 종류를 생성한다. 공통 지문·여러 줄 수식·그림 옆 본문·줄바꿈·그림 글상자 설정을 검사하며 PDF와 `checks.json`을 `output/migration-check/`에 남긴다. [입력 예제](examples/migration-compat.md)를 참고한다.

영어·수학의 보기 상자는 해당 과목의 일반 상자에 보기 제목을 추가한 구성이다. 원본의 별도 보기 표를 그대로 이식했다고 주장하지 않는다. 정답표·해설 출력은 기존 PyMuPDF 경로를 유지한다.

글꼴을 가져온 뒤 통합 검사를 켜려면 `$env:EXAMKIT_TYPST_ROOT=(Resolve-Path runtime).Path`와 `TYPST_EXE`를 설정한다. 그다음 `python -X utf8 -m unittest discover -s tests -v`로 실제 본문·표지 통합 검사를 실행한다. 본문 검사는 COM 모듈을 차단하고 새 문항, 메타데이터, 수식, 정답 세 가지 색, 실패 시 이전 PDF 보존을 확인한다. 전체 생성 명령도 별도 COM 차단 환경에서 실행했다.

한글 프로그램 없이 출력된다는 것과 한글 렌더링의 모든 픽셀이 같다는 것은 다르다. 수식 배치는 MathText, 문단 배치는 기존 원본 서식 엔진을 사용하며 한글과의 완전한 렌더링 동일성은 검증되지 않았다. 분할 불가능한 큰 표/그림은 내용이나 배치를 조정해야 한다. `--reuse`는 입력 변경을 자동 검증하지 않는다.

원본 저장소 PR은 유지관리자의 검토 후 병합 여부를 결정한다. 원본 글꼴·개인 문항·생성 PDF는 공개 커밋에 포함하지 않는다.
