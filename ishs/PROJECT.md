# 인천과학고 학교 생활 모의고사 지침

이 문서는 `content/1교시.md`~`4교시.md`와 해당 해설·그림에만 적용한다. 다른 학교·과목의 모의고사에 자동 적용하지 않는다. 공통 지침은 [AGENTS.md](../AGENTS.md), 출제·수정 노하우는 [docs/authoring-style.md](../docs/authoring-style.md), 세부 출제 원칙은 [prompt.md](../prompt.md)를 읽는다.

## 대상과 전제

- 대상은 인천과학고 재학생이다. 1교시는 지리(교내 장소·건물·이동), 2교시는 생활(기숙사·면학·급식·규정), 3교시는 문화, 4교시는 역사다.
- 재학생의 공유 상식은 문제에 모두 적지 않아도 된다. 해설에 '전제가 없다'는 경고를 넣거나 조건을 덧붙이지 않는다. 이번 해설 수정에서는 문제 원문·정답을 유지한다.
- 학교 사실의 로컬 참고 원문은 `C:/Users/User/Downloads/raw/`이다. 이 경로는 현재 PC에만 해당한다. 다른 환경에서는 자료 위치를 확인한다.
- 급식 봇은 다음 날 메뉴를 올리는 인스타그램 봇이다. 없는 누적 해시태그 등의 기능을 창작하지 않는다.

## 출제 취향과 형식

- 학교 생활을 학생이 알아볼 수 있는 소재로 삼고, 짧은 조건으로 계산·배치·순서·참거짓 추론을 하게 한다. 학교 이름만 붙인 교과 지식 문항으로 바꾸지 않는다.
- 소재 선택이 갈릴 때는 대안 2~4개를 제시한다. 사용자가 "일단 다 만들어 보라"고 하면 바로 쓴다.
- 사용자가 지정한 소재·장소·번호·좋다고 한 풀이 구조는 유지한다.
- 교시당 20문항, 3점 10개, 정답 ①~⑤ 각 4개를 검사한다. 같은 정보가 여러 문항의 정답을 노출하지 않게 한다.
- 실명·학번·개인 사건은 쓰지 않는다. 교장·학교 방침에 대한 반발, 휴대폰 수거 논란 등은 사용자의 명시적 요청이 있는 범위에서만 다룬다.
- 사용자가 요청하지 않은 '(가상)' 꼬리표는 붙이지 않는다. 실제 사실과 풀이용 가정은 문맥상 구분한다.
- `@status`는 사용자가 마지막으로 본 판 대비 keep/mod/new다. 해설만 고쳤다고 문항 상태를 바꾸지 않는다.
- 쪽수는 각 MD의 `pages`를 따른다. 기존 목표를 맞추려고 필요한 조건을 훼손하지 않는다. 큰 변경이 필요하면 그 이유를 알린다.

## 사용자 피드백에서 굳어진 인곽 전용 규칙

- 문항마다 정해진 장소·소재를 지킨다(예: 1교시 4번은 실험동, 1교시 17번 대화방 이름은 '인곽 32기'). 다른 건물·소재로 옮기지 않는다.
- 기수별 체육복 색, 동아리–분야(천수동=수학, TIP=물리), 1차 면학 감독 요일, 급식이 평일만 있는 것 등은 재학생 공유 상식이라 조건으로 적지 않는다.
- 수학 행사(로직 주최 파이데이·소수 찾기·피타고라스·키링)와 같은 사건의 두 문항(녹물 배관·녹물 앙금)은 번호를 떨어뜨린다. 4교시 20번(휴대폰 수거·기본권 킬러)은 20번 고정.
- 교장 이름은 어떤 문서에도 쓰지 않는다. 휴대폰 수거·녹물 사건처럼 사용자가 요청한 민감 소재는 "다음은 가상의 상황이다."로 시작하고 중립적으로 쓴다.
- 3교시 17번(폐부) 토론 그림에는 여화무가·책톡 이름을 쓴다. 4교시 R&E 문항은 본선에 전국 팀이 함께 오른 사실을 지키고, 포스터 제목은 '티라노가 이길까, 코끼리가 이길까?'(그림에 원근 합성, `hist_rne_final_02.png`).
- 쪽수: 1·2교시 4쪽, 3·4교시 6쪽. 4쪽 강제는 사용자가 풀었으므로 조건을 뭉개서 줄이지 않는다.
- 과거 그림 요청 묶음(handoff5~7: PROMPT.md·layout·style·DELIVERY)은 저장소 밖 `ISHS_Wiki/인곽생활_모의고사/handoffN_그림요청.zip`에 있다. 새 요청은 [삽화 요청서](../docs/illustration-request.md) 양식으로 쓴다.
- 실제 위키 원문 `C:/Users/User/Downloads/raw/`(이 PC 전용)로 사실을 대조한다. 다른 PC에서는 사용자에게 원문 위치를 묻는다.

## 그림 제작 방식

- 장면·인물·사물·자료의 장식 틀은 이미지 생성 도구로 만든다. API 연결을 기본 작업으로 추가하지 않는다.
- 그림은 글자 없는 흑백 틀로 받고, 제목·대사·이름표·수치를 문서 쪽에서 배치한다. 정확한 그래프·격자·조직도의 관계는 코드·도형으로 관리한다.
- 기존 그림체 기준과 요청서의 구도를 따른다. 요청서 양식과 납품 기록 형식은 [삽화 요청서](../docs/illustration-request.md).
- 글상자는 HWPX 도형을 우선하고, 원근이 필요한 특수 합성은 원본을 보존한 별도 파일로 만든다.
- 엔진별 세부 문법과 시행착오는 [HWPX 배치 노트](../docs/hwpx-layout-notes.md)를 본다.

## 원문과 산출물

- 문항: `content/N교시.md`; 해설: `content/N교시_해설.md`.
- 최종 PDF: `ishs/pdf/`. 현재 내용과 빌드 기록을 확인하고, 이 문서에 쪽수·완료 상태를 영구 규칙처럼 고정하지 않는다.
- 해설 서식: [실측 양식](../docs/explanation-format.md). 사용자 예시의 글꼴·용지·단·표를 기준으로 한다.
- 배포본은 매 교시 앞에 [원본 HWP 표지](../docs/cover-format.md)를 붙인다. 가형·나형·홀수형·주관식 문구를 없애고 필적 확인란에는 '지혜를 모아 지혜를 모아'를 넣는다. 문항 쪽수는 표지를 제외한 수다. 해설의 영역–과목–정답표 사이에 삭제한 공백을 되살리지 않고, 각 단 오른쪽의 추가 여백 약2mm를 유지한다.
- 참고 기출 원본과 crop은 제작 참고용이다. 공개 전환 작업에서 배포 범위를 확인하고 제외 대상으로 관리한다.
